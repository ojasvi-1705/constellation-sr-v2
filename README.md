# Constellation SR 🛰️
### Deep Learning-Based Super-Resolution Mapping from Medium-Resolution Satellite Imagery

**Constellation SR** is a prototype for satellite image super-resolution that aims to convert low-resolution satellite or aerial imagery into images with 2× higher spatial resolution using deep learning.

The project combines image preprocessing, deep learning-based super-resolution, tiled inference, and a web API to provide an end-to-end image enhancement workflow.

## ✨ Key Features

- **2× Image Super-Resolution:** Generates higher-resolution outputs from low-resolution inputs.
- **Deep Learning Models:** Supports EDSR and RCAN model options.
- **Image Preprocessing:** Includes radiometric calibration and atmospheric-correction stages in the processing pipeline.
- **Tiled Inference:** Processes larger images in overlapping tiles to help manage memory usage.
- **Multiple Input Options:** Supports uploaded images, image URLs, and bundled sample images.
- **Web API:** Provides endpoints for inference, batch processing, job status, and result downloads.
- **GPU Support:** Uses GPU acceleration when supported and detected by PyTorch; otherwise, it can run on the CPU.
- **Evaluation and Logging:** Records inference requests in SQLite and reports PSNR, SSIM, and SAM-based checks.

## 🧠 Project Workflow

The current processing pipeline is:

**Input Image → Preprocessing → Deep Learning Super-Resolution → Output Image**

1. **Input:** A satellite or aerial image is provided by upload, URL, or sample selection.
2. **Preprocessing:** The image passes through the configured radiometric-calibration and atmospheric-correction stages.
3. **Super-Resolution:** An EDSR or RCAN model generates a 2× higher-resolution image.
4. **Tiled Inference:** Larger inputs are processed in tiles with overlap to help manage memory consumption.
5. **Output:** The resulting image is saved as a PNG file.
6. **Evaluation and Logging:** The request and available image-quality checks are recorded for inspection.

## 🗂️ Dataset

### UC Merced Land Use Dataset

This project uses the **UC Merced Land Use Dataset** for initial experimentation and model training.

The original dataset contains 2,100 aerial images across 21 land-use categories, with 100 images per category. The images are RGB and have a resolution of 256 × 256 pixels.

- **Dataset:** UC Merced Land Use Dataset
- **Original source:** [UC Merced Land Use Dataset](http://weegee.vision.ucmerced.edu/datasets/landuse.html)
- **Research reference:** Yang, Y. and Newsam, S. (2010), *Bag-of-Visual-Words and Spatial Extensions for Land-Use Classification*, ACM SIGSPATIAL.

The trial copy used by this project contains 16 of the original 21 classes.

### Preparing Low-Resolution Inputs

For the standard super-resolution training setup, low-resolution inputs are generated by bicubic downsampling of the original images by a factor of 2. The corresponding original images act as high-resolution reference targets.

This provides paired low- and high-resolution examples for training and evaluation.

**Dataset note:** The UC Merced dataset consists of aerial imagery and is used here as a trial dataset for super-resolution experiments. It is not a paired Sentinel-2 dataset. Results on this dataset alone should not be interpreted as proof of performance on operational medium-resolution satellite imagery.

The repository includes a local dataset copy under `data/ucmerced`. Refer to `download_data.py` for the dataset preparation workflow.

## 🚀 Installation and Setup

### Prerequisites

- Windows, Linux, or another compatible Python environment
- Python 3.11 recommended for the documented Windows setup
- Git
- pip
- A CUDA-compatible GPU and compatible PyTorch installation for GPU acceleration (optional)

### 1. Clone the Repository

```bash
git clone https://github.com/ojasvi-1705/constellation-sr-v2.git
cd constellation-sr-v2
```

### 2. Create a Virtual Environment

A virtual environment keeps the project's Python packages separate from other projects on your computer.

**Windows (Command Prompt):**

```cmd
python -m venv venv
venv\Scripts\activate
```

**Linux/macOS:**

```bash
python3 -m venv venv
source venv/bin/activate
```

The local `venv/` directory is excluded from GitHub. Create your own environment instead of downloading or copying the developer's environment.

### 3. Install Dependencies

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

For GPU acceleration, install a PyTorch build compatible with your operating system, Python version, and CUDA requirements. Consult the [official PyTorch installation guide](https://pytorch.org/get-started/locally/).

### 4. Verify GPU Availability

```bash
python check_gpu.py
```

This script helps diagnose whether PyTorch can detect the available GPU.

## 🏋️ Training the Model

### Download the Trial Dataset

```bash
python download_data.py
```

### Train EDSR

```bash
python train.py --data data/ucmerced --model edsr --iters 6000 --bs 8
```

The training script supports model and training-parameter options. Check `python train.py --help` for the available arguments.

The documented EDSR workflow saves weights to `weights/edsr.pth`. Check the training output and configuration to confirm the checkpoint path for your run.

The repository also supports the RCAN model option. Model performance depends on the dataset, preprocessing, training configuration, and checkpoint used.

## ▶️ Running the Application

Start the FastAPI application with Uvicorn:

```bash
python -m uvicorn api.app:app --reload
```

Once the server starts, open:

**http://127.0.0.1:8000**

The API documentation, if enabled by the application, is generally available at:

**http://127.0.0.1:8000/docs**

## 📊 Evaluation

The application records the following image-quality metrics:

- **PSNR (Peak Signal-to-Noise Ratio):** Measures pixel-level reconstruction error.
- **SSIM (Structural Similarity Index):** Measures structural similarity between images.
- **SAM (Spectral Angle Mapper):** Measures spectral similarity where the input data and implementation support a meaningful spectral comparison.

The application's existing comparison against a bicubic-upscaled input is a sanity check, not definitive evidence of reconstruction accuracy. A rigorous evaluation should use ground-truth high-resolution reference images and a clearly defined test set.
